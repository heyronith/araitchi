# Task 7 — Convene gate (Auto mode) and task-specific merging

Repo: `heyronith/araitchi` (Task 6 done at `3f06ffc`). Read `AGENTS.md`, `docs/STATUS.md`, `docs/ARCHITECTURE.md` first. Save these instructions as `docs/tasks/T07.md`.

**Goal:** in **Auto** mode every request gets the cheapest action that can be trusted — *retrieve evidence*, *solo*, *probe*, or *council* — with a logged, visible reason. Council replies are merged according to the task type. **Selection principle: quality first** — every model default in this task is chosen by evaluation results, not price. **Out of scope:** validation loop (Task 8).

## 0. Housekeeping
`scripts/eval-scribe.mjs` defaults to outdated models (gpt-4o era). Replace defaults with OpenRouter "latest" aliases (e.g. `~anthropic/claude-opus-latest`, `~openai/gpt-latest`, `~google/gemini-flash-latest`) and let models be passed as CLI args. Same pattern for every eval script in this task.

## 1. Task taxonomy (shared by classifier, merge modes, UI)
`hypothesis_generation`, `experiment_design`, `literature_review` (incl. novelty check), `critique`, `results_interpretation` → **always council**.
`factual_lookup` (facts, definitions, "what does paper X say", citations) → **retrieve evidence**.
`chat`, `formatting`, `summarize_single`, `repo_status`, `code_help`, `planning_admin` → **solo**.
`other` → **probe**.
Plus a separate `stakes: low|medium|high` and `needs_evidence: boolean`. Keep the taxonomy in one file (`src/lib/server/gate/taxonomy.ts`).

## 2. Classifier (three layers)
1. **Rules:** explicit overrides (`/solo`, `/council`, `/probe`, `/evidence`), mode forced by the user (Solo/Council), obvious patterns (pasted DOI/arXiv id → factual_lookup; "what changed" + repo → repo_status).
2. **Embedding kNN** using the Task 6 embedder: a labeled seed set `src/lib/server/gate/seed-examples.json` of **≥ 300 examples** (≥ 20 per task type, research-flavoured, including hard/ambiguous ones). Classify by weighted kNN; accept if confidence ≥ threshold (tuned on the eval, stored in config).
3. **LLM fallback** for low-confidence cases: structured output `{ taskType, stakes, needsEvidence, reason }`. Setting `gate.classifierModel`. The default is chosen by `pnpm eval:gate` (below) — the **most accurate** candidate whose median latency is ≤ 3 s; ship a sensible current default via a "latest" alias and document how to change it.
The user can correct a classification from the UI ("Should have been: …"); corrections are stored and added to the kNN examples for that project.

## 3. Actions
- **Retrieve evidence:** one strong model (the user's default solo model) with Papers + Web + Memory tools forced on and prompt `prompts/evidence.md`: answer only from retrieved sources, cite every claim (DOI/arXiv/URL/[record id]), say "not found" rather than guess.
- **Solo:** current behaviour.
- **Probe:** two models from **different labs** (setting `gate.probeModels`, default chosen by eval) answer in parallel. Measure **semantic agreement**: embed both answers (and their extracted key claims) with the local embedder; agreement score = cosine of claim sets (document the method). Agree (≥ threshold) → return the better-scored answer (the probe pair's own self-rated confidence, tie → first). Disagree → escalate to council, reusing both probe answers as two council members (don't pay twice). **Agreement is never treated as proof:** if `needsEvidence` is true, an agreed answer still goes through *retrieve evidence* verification of its key claims.
- **Council:** Task 4 pipeline + merge mode below.
- Research-critical requests may set a `needsValidation` flag on resulting hypothesis/experiment records (consumed by Task 8).

## 4. Task-specific merge modes (synthesizer prompt variants in `prompts/merge/`)
- `literature_review`: union of all members' papers, dedupe by DOI/arXiv/title (reuse Task 5 merger), rank, then a review organised by theme; list papers only one member found.
- `hypothesis_generation`: keep **distinct** hypotheses (cluster near-duplicates by embedding similarity, don't average), each with rationale, testable prediction and critique; ranked with reasons.
- `experiment_design`: merged protocol + alternatives, each with predeclared success/failure criteria, controls, threats to validity.
- `critique`: union of issues, severity-ranked, which member raised each.
- `results_interpretation` and factual disagreements: **evidence-grounded resolution** — a claim backed by a cited source beats an uncited majority; unresolved → `needsEvidence: true`.
- Generic synthesis for anything else.

## 5. Decision log and UI
- Table `gate_decisions` (project DB): message id, input hash, layer used (rule/kNN/LLM), taskType, stakes, needsEvidence, confidence, action, models, estimated vs actual cost, probe agreement score, escalated?, user correction, latency, created_at.
- **Auto** is enabled and becomes the **default mode**. Above each reply: a small chip "Auto → Council · hypothesis generation · high stakes" with a **"Why?"** popover (layer, confidence, reason, cost) and "Re-run as Solo / Council".
- Settings → Routing: thresholds, models (classifier, probe pair), always-council list (editable), budget behaviour.
- A **Routing log** view (table of recent decisions with filters) for transparency.

## 6. Evaluations (manual, real key; fixtures committed)
- `pnpm eval:gate [models…]`: a held-out labeled set `evals/gate/` (**≥ 150 examples**, not in the seed set) → accuracy, per-class F1, confusion matrix, latency, cost per classification for: kNN only, kNN + each candidate LLM, LLM only, and a **difficulty-only baseline** (simple length/keyword rule). Target: overall accuracy ≥ 85% and always-council recall ≥ 95%.
- `pnpm eval:probe [modelA modelB]`: 40 question fixtures with known agreement/disagreement outcomes → agreement threshold ROC, chosen threshold.
- Report tables go to `evals/results/*.md` (committed).
