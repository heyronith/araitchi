## 1. OpenRouter authentication
- Base URL from `process.env.ARAITCHI_OPENROUTER_BASE_URL ?? 'https://openrouter.ai/api/v1'` (used by tests to point at a mock). Central server-only module `src/lib/server/openrouter.ts`.
- **OAuth PKCE (primary):**
  - `GET /api/openrouter/connect`: generate a random `code_verifier` (≥ 43 chars, base64url), compute S256 `code_challenge`, store the verifier in an **httpOnly, SameSite=Lax, 10-minute** cookie, then redirect to `https://openrouter.ai/auth?callback_url=http://localhost:<PORT>/api/openrouter/callback&code_challenge=<…>&code_challenge_method=S256`.
  - `GET /api/openrouter/callback?code=…`: read verifier from the cookie (fail clearly if missing), `POST <base>/auth/keys` with `{ code, code_verifier, code_challenge_method: "S256" }`, store returned `key` via `setSecret('openrouter_api_key')`, delete the cookie, redirect to `/?connected=openrouter` (show a success toast). Errors redirect to `/?connect_error=<short reason>` (toast). Never put the key in a URL or log.
- **Manual key** (existing Settings field) stays as a fallback.
- **Test connection:** `POST /api/openrouter/test` calls OpenRouter's current-key info endpoint (`GET <base>/key`; confirm against OpenRouter docs) and returns only non-secret info (label, usage, limit/remaining credits). Show it in Settings next to the key (“Connected · $X.XX remaining” or “Invalid key”).
- Settings → Keys: add a prominent **“Connect with OpenRouter”** button above the manual field, and a **Disconnect** action (deletes the secret).
- Send attribution headers on all OpenRouter calls: `HTTP-Referer: http://localhost:<PORT>` and `X-Title: Araitchi`.

## 3. Streaming solo chat
- **Server:** `POST /api/chat` (Node runtime, origin guard, zod validation: `chatId`, `modelId` matching `^[\w.-]+/[\w.:-]+$`, messages ≤ 200 and total text ≤ 500k chars). Use the AI SDK `streamText` with `@openrouter/ai-sdk-provider` (key read server-side from secrets — **never sent to the browser**). Support abort (client stop cancels the upstream request). Request usage accounting so the response includes tokens and **cost**. If the model returns reasoning, stream it as a separate collapsible part.
- **Client:** assistant-ui with its AI SDK integration (install `@assistant-ui/react-ai-sdk` and `@assistant-ui/react-markdown` if needed). Requirements:
  - Markdown with GFM tables, syntax-highlighted code blocks (shiki), **copy button on every code block**, and copy for the whole message.
  - **Stop** while streaming; **Retry/regenerate** on assistant messages; **Edit** a user message → creates a **branch**; branch switcher (‹ 1/2 ›).
  - Model picker in the composer toolbar; the chosen model is recorded per assistant message.
  - Small footer per assistant message: model name · tokens in/out · cost (e.g. `$0.0012`).
  - Auto-scroll, “scroll to bottom” button, Enter to send / Shift+Enter newline, autofocus.
  - If no key: composer disabled with a CTA “Connect OpenRouter to start” opening Settings.
  - Friendly errors (inline in the thread with Retry, plus toast) for invalid key (401), no credits (402), rate limit (429), model unavailable, network errors.
- **Persistence (app DB for now; Task 3 moves chats into project folders):** Drizzle tables `chats(id, title, created_at, updated_at)` and `messages(id, chat_id, parent_id, role, parts JSON, model_id, usage JSON, created_at)` so branches are a tree. Load a chat with its full branch tree and active branch.
- **Sidebar “Chats”:** list (newest first), **New chat** (enabled now), rename, delete (with confirm). Title = first user message truncated to ~60 chars (no extra LLM call).
