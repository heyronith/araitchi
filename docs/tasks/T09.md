## Part A — Benchmark harness (`pnpm bench`, manual, real OpenRouter key)

### A1. Configurations (same model pool for all)
- **A — Strongest solo:** the single strongest model, tools on.
- **B — Always council:** every item goes to the council (task-specific merge on).
- **C — Adaptive:** Auto mode (convene gate) as shipped.
- **D — Adaptive + validation:** C plus the Task 8 validation loop where the task has an experiment.
Run the app's real pipelines headlessly (a bench runner that calls the same server modules, not the UI). Fixed per-item **budget cap** (configurable, default $0.50) for every config; record actual cost.

### A2. Task sets (fixtures in `evals/bench/`, each item with a machine-checkable answer)
1. **Verifiable questions (40):** research-flavoured questions with ground truth checkable by code — numeric (with tolerance), exact entities, DOIs, dates. Checker functions are fixed code in the harness (never model-written code).
2. **Literature recall (30):** research questions with a **gold set of relevant papers** (DOIs/arXiv ids, e.g. from the reference lists of published surveys). Metric: recall@20 of gold papers among the reply's sources, plus precision of cited sources (do they exist and resolve).
3. **Rediscovery (15):** published findings with literature search restricted to **before the publication year** (`yearTo` cutoff enforced in the tool broker for the run). Metric: is the true finding among the top-3 hypotheses? Score with a fixed rubric of required key terms/relations per item **plus** embedding similarity ≥ threshold to the gold statement; flag borderline cases for **human review** in the report (no LLM-as-judge for the final score).
4. **Validation (10, config D vs C):** hypotheses with known real outcomes encoded as fixture `results.json` files (the harness plays the role of "you ran it in Cursor"). Metric: correct verdict rate and whether predictions were locked before results were seen.

### A3. Metrics and reporting
- Per config × set: verified correctness / recall / rediscovery hit rate / verdict accuracy, **cost per item, cost per verified-correct item**, latency, gate decisions (for C/D).
- Run each config **3 times**; report mean and 95% bootstrap CI.
- Output `evals/results/bench-YYYY-MM-DD.md` (tables + short findings) and `.json`; `pnpm bench --sets 1,2 --configs A,C --limit 5` for quick runs.
- **In-app:** Settings → **Evaluations** page that loads the latest result JSON and shows the tables and a simple bar chart per metric (no network calls from that page).
- The default-model results from `eval:scribe`, `eval:gate`, `eval:probe` also render on this page if present.
