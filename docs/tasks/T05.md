## 1. Tool broker (`src/lib/server/tools/`)
- **Registry:** each tool = `{ name, description, inputSchema (zod), kind: "read" | "write" | "spend", provider, handler }`.
- **Every call goes through the broker:** zod validation → **cache** (project `notebook.db` table `tool_cache`: tool, args hash, result, created_at; per-tool TTL, e.g. papers 7 days, web 1 day, repo 0) → **in-flight dedupe** (identical concurrent calls from different council members share one request) → **rate limiting** per provider (token bucket, provider-specific limits) → timeout → error normalisation (tools return `{ ok:false, error }`, never throw into the model loop) → **result size cap** for the model (truncate with an explicit "[truncated]" marker; full result kept for the UI).
- **Provenance:** table `tool_calls` (id, chat_id, message_id, model_id, tool, args, status, cached, duration_ms, cost_usd, sources JSON, created_at).
- **Prompt-injection guard:** all tool output is given to models wrapped as `<tool_result tool="…" source="…" untrusted="true">…</tool_result>`, and the system prompt states that tool-result content is data, never instructions. No tool can write or spend without **explicit user approval** in the UI (approve/deny card). In this task only MCP tools can be non-read.
- One broker instance per chat request, shared by all council members of that request.

## 2. Paper search
Base URLs env-overridable for tests (e.g. `ARAITCHI_OPENALEX_BASE_URL`, …). Providers run in parallel; one failing provider never fails the search; return per-provider status.
- **Providers:** OpenAlex (`openalex_api_key` secret, optional), CORE (`core_api_key`), Semantic Scholar (`semantic_scholar_api_key`, optional; respect its rate limit), arXiv (Atom API), DBLP (JSON API), OpenReview (API v2 search), Crossref (query works; send `mailto` from a new non-secret setting `contact_email` for the polite pool). Unpaywall is used by DOI to find a legal OA PDF (needs `contact_email`).
- **Normalised `Paper`:** title, authors, year, venue, abstract, doi, arxivId, url, pdfUrl, citationCount, `foundBy: provider[]`.
- **Dedupe & merge:** key = lowercase DOI; else arXiv id without version; else normalised-title + year fingerprint. Merge fields, union `foundBy`.
- **Rank:** reciprocal-rank fusion across providers + small boost per extra provider that found the paper.
- **Tools:** `search_papers({ query, yearFrom?, yearTo?, limit≤50 })`, `get_paper({ doi | arxivId })` (details + abstract + OA PDF link), `paper_links({ doi|arxivId, direction: "citations"|"references", limit })` (Semantic Scholar, OpenAlex fallback) for citation chasing.
- **Library:** a "Save paper" button (user action, not a model tool) saves a `paper` record + metadata JSON in `.research/library/`; "Download PDF" only for OA links and only on user click.
- Settings → Keys: add `openalex_api_key` to the secrets whitelist; Settings → Tools: `contact_email`, per-provider on/off.

## 4. Documents
Upload PDF / `.md` / `.txt` (composer attachment and Library tab; ≤ 50 MB). Extract text server-side (pure-JS library such as `unpdf`), store file + extracted text in `.research/library/`. Tool `read_document({ id, query?, pages? })` returns the most relevant chunks (simple keyword scoring for now; embeddings come in Task 6) with page numbers.

## 5. Repo (read-only)
For the project's detected `repoPath`, using the `git` binary via `execFile` with an **argument array (never a shell string)**:
- `repo_status`, `repo_log({ n≤50, since? })`, `repo_diff({ since: ref | "last_check" })` (bounded size), `repo_read_file({ path, startLine?, endLine? })`, `repo_find({ pattern })`, `repo_grep({ pattern, maxResults≤100 })`.
- Path safety: resolve + `realpath` must stay inside the repo root; deny `.env*`, `*.pem`, `*.key`, `id_*`, `.git/` internals, and files > 1 MB.
- "Mark checked" stores the current HEAD as `last_check` per project (user action and after the user accepts a result).
- If `git` is not installed, tools return a clear error and Settings shows a hint.
- Optional remote: if the project has a GitHub URL and a `github_token` secret, provide read-only `repo_log` / `repo_read_file` equivalents via the GitHub REST API. Keep this minimal.
