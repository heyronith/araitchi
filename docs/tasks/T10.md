### 2b. Keys: work well with zero keys, better with optional free keys
**Do not bake project-owned API keys into the repo or app.** It's public MIT code: any embedded key is extractable, one shared quota would be rate-limited for every user at once, and the providers' terms make keys per-account (Semantic Scholar's licence is non-transferable; OpenAlex keys carry a per-account daily budget).
Instead:
- **Keyless by default:** arXiv, Crossref, DBLP, OpenReview, Unpaywall (with `contact_email`) and **unauthenticated** Semantic Scholar/OpenAlex calls (with caching, backoff, concurrency 1, and the shared anonymous limits respected) must give a useful result out of the box.
- **Onboarding step "Boost paper coverage (optional, free, ~2 min)":** one card per provider (OpenAlex, Semantic Scholar, CORE) with what it adds, a direct link to its free-key sign-up page, a paste field, and a live "test key" check. Skippable; also reachable from Settings → Keys.

## 5. Evaluation sets: use public benchmarks where they exist, build our own only where none fit
For every external dataset: check and record its licence in `evals/SOURCES.md`; don't commit data whose licence forbids redistribution (download at eval time instead, with a pinned version/hash).
- **Literature search → adopt [LitSearch](https://arxiv.org/abs/2407.18940)** (EMNLP 2024: 597 expert-checked literature-search questions about ML/NLP papers, each with ground-truth papers). Add `pnpm eval:litsearch` (recall@5/@20 of ground-truth papers from our `search_papers` + solo/council configs). It replaces our self-built set 2 as the headline literature metric; keep set 2 as a secondary check.
- **Paper finding and long-form CS research Q&A → adopt Ai2 AstaBench subsets** where licensing allows: **PaperFindingBench** and **ScholarQA-CS2** (CS-focused, matches our users). Add as optional bench sets (`--sets paperfinding,scholarqa`). LitQA2 (biomedical) only as an optional extra.
- **Probe agreement → build labels from real model behaviour on a public QA set with ground truth** (e.g. a science multiple-choice set such as GPQA-Diamond, licence permitting): run the probe pair on each question; ground truth tells whether each answer is right, so "agree but wrong" and "disagree" cases are real, not invented. Tune the threshold on ≥ 200 such items; report how often agreement hides a shared wrong answer.
- **Routing (gate) → keep our own set** (no public benchmark uses our taxonomy), but grow it with ≥ 150 more examples written to be hard and ambiguous, and add an **opt-in "share anonymised routing corrections"** export the owner can review and add to the eval set later. Nothing leaves the machine automatically.
- **Scribe → keep our own set** (no public benchmark extracts into our record types) and add **20 harder cases** (long multi-turn chats, several records per turn, updates vs duplicates, tempting-but-unsupported claims). Optionally use LongMemEval-style questions to test *recall* across sessions.
- Re-run probe, scribe and gate evals live on the new sets; LitSearch with `--limit 50` within the spend limit.
