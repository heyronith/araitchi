## 1. Project model
- A project is any folder. Opening it creates (idempotently) :
  ```
  <folder>/.research/
    project.json     { id, name, createdAt, schemaVersion: 1, repoPath|null }
    brief.md         template: Goal / Constraints / Key definitions / Out of scope
    notebook.db      per-project SQLite (WAL)
    library/         (empty for now)
    sessions/        chat transcripts as markdown
    memory.md        readable export of the notebook
    .gitignore       ignores notebook.db-wal, notebook.db-shm, .lock
  ```
- **Repo detection:** if `<folder>/.git` exists, or a direct subfolder contains `.git` (prefer `code/`), store its path in `project.json.repoPath`. **Never write inside the user's repo** other than `.research/` at the project root.
- **Lock:** `.research/.lock` with PID + timestamp; if another live process holds it, show a warning and open read-only.
- **App DB:** new `projects` table (`id`, `name`, `path`, `last_opened_at`) for the recent-projects list. Store `current_project_id` in settings.
- **Scratch project:** create `<dataDir>/scratch/` as a default project so chatting never requires choosing a folder.
- **Migration:** move existing chats/messages from the app DB into the Scratch project's `notebook.db` (one-time, idempotent), then drop the old tables in a new app-DB migration.

## 2. Per-project database (`notebook.db`, Drizzle, separate migrations folder `drizzle/project/`)
- `chats`, `messages` (same shape as Task 2, moved here).
- `records`: `id`, `type` (`hypothesis|experiment|decision|paper|question|note`), `title`, `body` (markdown), `status` (hypothesis: `proposed|testing|supported|refuted|inconclusive`; experiment: `planned|running|done`; question: `open|answered`; others null), `pinned` (bool), `source` (`user` or a model id), `source_chat_id`, `source_message_id`, `tags` JSON, `created_at`, `updated_at`, `deleted_at` (soft delete).
- **FTS5** virtual table over `records(title, body)` kept in sync (triggers); used for search.
- Server-only module `src/lib/server/project/` (open/init, lock, db, records repo, exporters). All paths built with `node:path` (must work on macOS and Windows).

## 3. Exports kept in sync
- **`memory.md`:** regenerate after every record change. Group by type; show status, pinned first, source, dates. Excludes deleted.
- **`sessions/`:** after each completed assistant reply, write/overwrite `sessions/YYYY-MM-DD-<chat-slug>-<shortId>.md` with the chat's active branch (role, model, timestamp, content).

## 4. Brief and pinned memory reach the model (simple version)
For every chat request, prepend a system message built from: `brief.md` (cap ~2,000 tokens, approximate by characters) + titles and one-line bodies of **pinned** records (cap ~1,000 tokens). Read `brief.md` fresh each request so external edits apply. Show a small "Using project brief + N pinned" indicator above the composer.

## 5. Opening projects (UI + API)
- `GET /api/fs/list?path=` lists **subdirectories only** (no file contents), restricted to the user's home directory and below; rejects anything that resolves outside home (handle `..`, symlinks via `realpath`). Origin guard on all `/api/projects*` and `/api/fs*` routes.
- **Open folder dialog:** breadcrumb folder browser starting at home, "New folder" button, plus a "Paste a path" input (absolute path; must exist and be a directory; allowed anywhere but show the full path before confirming). Shows whether a repo was detected.
- `POST /api/projects/open` `{ path }`, `GET /api/projects` (recent), `POST /api/projects/switch` `{ id }`, `DELETE /api/projects/:id` (removes from recents only; never deletes files).

## 6. UI
- **Sidebar:** current project (name, path tooltip, copy-path button), recent projects, "Open folder…", "New project…" (create a folder then open). Chats list is scoped to the current project.
- **Top bar:** project name; repo badge if detected.
- **Memory panel** (right side, collapsible, remembers state): tabs **Brief · Hypotheses · Experiments · Decisions · Papers · Questions · Notes**.
  - Brief: markdown editor with preview; saves to `brief.md` (debounced, plus explicit Save).
  - Record lists: search box (FTS), filter by status, pinned first; each row shows title, status pill, source badge ("You" or model name), date. Add/Edit dialog (title, body markdown, status, tags), Pin toggle, Delete (soft, with Undo toast).
- **"Save to memory"** action on every chat message (and on selected text within a message): dialog prefilled with the text, choose type, saves with `source` = that message's model (or `user`) and links `source_message_id`. Records link back to their message.
- Empty states that explain what each memory type is for, in one line.
