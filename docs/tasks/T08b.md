# Task 8b — Security fix: confine experiment results path to the repo

Repo: `heyronith/araitchi` (at `099046f`). Save as `docs/tasks/T08b.md`. **Small, focused fix — no other changes.**

## Problem
`src/lib/server/experiments/verdict.ts` reads `exp.resultsPath` with `path.isAbsolute(filePath) ? filePath : path.join(repoPath, filePath)`. `resultsPath` comes from the design draft (client-supplied, zod only checks length). An absolute path or `../…` lets the verdict engine read **any file on the machine**, bypassing the Task 5 read-only repo safety (realpath confinement + denylist).

## Fix
1. **At design time** (`types.ts` zod + store): `resultsPath` must be a **relative** POSIX path, no `..` segments, no leading `/` or drive letter, ending in `.json`, and must be inside `experiments/<experimentId>/`. Default it to `experiments/<id>/results.json`; reject anything else with a clear error.
2. **At check time** (`verdict.ts`): resolve the file **only** through the existing Task 5 repo path-safety helper (`src/lib/server/tools/repo/paths.ts` — realpath must stay inside the repo root, denylist applies). Remove the `path.isAbsolute` branch entirely. Re-validate the stored `resultsPath` even for experiments created before this fix (old rows with unsafe paths → `inconclusive` with reason "unsafe results path").
3. **No content leakage:** error/inconclusive messages and stored verdict evidence must never include raw file contents — only paths, sizes, and schema error locations (field names), truncated.
4. Apply the same confinement to any other place in `src/lib/server/experiments/` that reads files from the repo (e.g. instructions/report writers must write only under `.research/experiments/<id>/`).

## Tests
- Vitest: absolute path, `../../x.json`, Windows-style `C:\x.json` and `..\\x.json`, symlink pointing outside the repo, `.env.json`-style denylisted names → all rejected at design time and/or check time; a legacy row with an unsafe path → inconclusive without reading the file; schema-error message does not contain file content.
- Existing e2e must still pass.
