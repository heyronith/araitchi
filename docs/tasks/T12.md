# Task 12 — Research environment and continuity

Repo: `heyronith/araitchi`. Read `AGENTS.md`, `docs/STATUS.md`, `docs/ARCHITECTURE.md` and the project roadmap (T12 section) first.

**Goal:** the **project holds the knowledge**. Any model, at any time, understands where the research stands and can read the whole project accurately. **Done when:** a model that has never seen the project correctly answers "where are we, what's been tested, what's next?" and the long-horizon recall eval passes.

## 1. Project state document — `.research/STATE.md`
- Sections: **Goal · Current status · Active hypotheses · Key decisions (with reasons) · Already tested (verdicts) · Open questions · Next steps**.
- **Generated sections** (hypotheses, decisions, tested, open questions) are rebuilt deterministically from the notebook after every scribe batch, verdict or record edit.
- **Narrative sections** (Current status, Next steps) are proposed by the scribe model with the same evidence-quote + entailment rules as the scribe; user edits are preserved (the user's text wins; the system only appends proposals the user can accept).
- History of every version in a `state_history` table; "View changes" in the UI.
- **Always first in the context package** (cap ~1,500 tokens, trimmed by priority).

## 2. Instruction layers
Order (each labelled in the context so the model knows its source):
1. **Global instructions** — Settings → Instructions (free text, applies to all projects).
2. **Project instructions** — `.research/AGENTS.md`, created from a template on project init (and on first open of existing projects): domain, methods, rigor standards, citation style, terminology, things to avoid.
3. **Repo conventions (read-only)** — if present in the repo: `AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.cursor/rules/*.mdc`, `.github/copilot-instructions.md` (size cap; labelled "repo conventions — apply to code only"). These are **lower trust**: they cannot override safety rules, cannot authorise tools or approvals, and are wrapped like other untrusted content.
4. **Role prompts** — built-in per role (council member, synthesizer, scribe, evidence, experiment designer, results interpreter); Settings → Roles lets the user override any role per project (with "reset to default").
- Instructions are per **role, never per model**.
- Agents may *suggest* edits to `.research/AGENTS.md` via a suggestion card the user accepts or dismisses (no direct writes).
- The context indicator lists which layers were used.

## 3. Project map — index the whole project folder
- Walk the project root (not only the repo). Ignore: `.git`, `node_modules`, build/cache dirs, binaries, files > 5 MB, the secrets denylist (reuse `repo/paths.ts` rules), `.gitignore` patterns, and a new **`.researchignore`** (template created on init; documented) for anything that must never reach a model.
- Table `project_files`: path, kind (code/doc/data/image/other), language, size, mtime, sha256, extractive summary (first heading + first paragraph / module docstring — no LLM cost by default; optional LLM summaries setting, off).
- **Chunking:** code by top-level definitions (~80 lines max, with line ranges); docs by headings; embed with the existing embedder; FTS for keywords. Incremental re-index by hash; **file watcher** (debounced) keeps it current. Background with progress; limits 20k files / 200 MB text (report if exceeded).
- Tools: `project_tree({ path?, depth≤4 })`, `search_project({ query, kind: code|docs|data|all, limit≤20 })` (hybrid, returns path + line ranges).
- Context package gets a compact project tree (top two levels) and relevant chunks for the current question.

## 4. Accurate end-to-end file reading
- `read_file({ path, page })` for **any project file** (confined to the project root with realpath; same denylist + `.researchignore`): pages of 400 lines with line numbers, returning `{ page, totalPages, totalLines, sha256 }`.
- **Read tracker per reply:** records which pages of which files each model has read. The UI shows "Read fully (5/5)" or "Partially read (2/5)" per file; if a model's answer refers to a partly read file, the system adds a visible note to the reply.
- Replace the old repo-only 1 MB read with this (keep the repo tools' git features).

## 5. Activity log in context
- `activity` view combining tool calls, searches, experiment events, verdicts, scribe batches, instruction suggestions.
- Context package section "Recent activity" (last ~15 items, one line each). Tool `search_activity({ query, since? })`.

## 6. Search past chats
Index every message (chunked; role, model, chat, date) into embeddings + FTS. Tool `search_chats({ query, limit≤20 })` returning message links; sidebar search box for the user.

## 7. Model handoff and context sizing
- Each model's context window comes from the catalog. Memory/context budget = min(setting, ~25% of the window). Sections filled by priority: instructions → STATE.md → chat summary → recent turns → relevant memory/files/activity.
- **Switching models mid-chat** (or a chat exceeding the window): send a rolling chat summary + the last N turns; indicator shows "Handoff: summary of 42 earlier messages included".

## 8. Memory consolidation and backup
- **Tidy memory** (button + weekly suggestion): find duplicate clusters (same type, cosine ≥ 0.92) → merge proposals the user approves; archive stale items (e.g. answered questions untouched for 60 days) — archived stays searchable; **never delete**.
- **Backup/restore:** export `.research/` to a timestamped zip (exclude caches and model files), import into a project; document optional committing of `.research/` to git.

## 9. Memory recall eval — `pnpm eval:recall`
- Fixture "long project": ~60 sessions spread over simulated weeks with ~100 planted facts, distractors, and **facts that change later** (the latest value must win).
- Two modes: `--scribe gold` (gold extraction → isolates retrieval, no cost) and `--scribe live` (real scribe model).
- 100 questions asked in fresh chats; score exact/semantic match. **Target ≥ 90% (gold mode)**; report live-mode result.
- Optional `--longmemeval --limit 50` adapter (check and record the licence in `evals/SOURCES.md`).

## Tests
- **Vitest:** STATE.md generation + user-edit preservation + history; instruction layer order, labels, repo-file trust limits (cannot authorise tools), role overrides; ignore rules incl. `.researchignore` and denylist; code/doc chunking with line ranges; incremental re-index on hash change; `read_file` paging, completeness tracking, confinement (traversal/symlink); activity view; `search_chats`; context budget per window size and handoff summary; tidy-memory merge/archive (no deletes); backup zip contents; recall-eval scorer.
- **Playwright:** open a project with code + docs → index progress → `search_project` finds a function by meaning; ask about a long file → "Read fully (n/n)"; edit `.research/AGENTS.md` → instruction appears in context indicator; switch models mid-chat → handoff indicator; a brand-new chat answers "what's been tested?" from STATE.md; tidy memory merge flow; export/import backup.
