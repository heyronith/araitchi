# Task 9b — Make the benchmark real (v0.1.1)

Repo: `heyronith/araitchi` (v0.1.0 at `09697e7`). Save as `docs/tasks/T09b.md`.

## Problems found in review
1. **The live benchmark is not live.** `src/lib/server/bench/runner.ts` always uses `mockReplyForItem(...)` — even when `dryRun` is false. Costs are hard-coded (`0.05`, `×3`, `×1.2`), set 3 scores with `FakeEmbedder`, and config D on set 4 is marked correct "by construction". Results from `pnpm bench` are therefore meaningless.
2. **The fixtures are templated placeholders** (e.g. "Survey key papers on topic 0 … topic 1 …" with the same two gold papers; verifiable items like "What is the DOI for BERT DOI?"). They can't measure anything.

## Part 1 — Live runner (dry-run stays mock-only)
- Move all mock logic into `src/lib/server/bench/mock.ts`, used **only** when `dryRun` is true. Add a Vitest test with a spy proving the live path never calls the mock.
- **Live path calls the real server pipelines headlessly** (same modules as `/api/chat`): build a temp project folder per (config × item × repeat) with a fresh `.research/` (no memory leakage between items), real OpenRouter key, tools on, real usage/cost accounting, and a per-item budget cap that aborts the run when exceeded.
  - **A:** solo with the strongest model from `config/defaults.json`.
  - **B:** forced council with the task-specific merge mode for the item's labelled task type.
  - **C:** Auto mode (real convene gate decisions recorded).
  - **D:** Auto + validation loop. For set 4: the real model designs the experiment → predictions are locked by the real lock code → the harness commits the fixture `results.json` into a temp git repo (simulating Cursor) → the **real verdict engine** checks it → compare with `expectedVerdict`. Never mark correct by construction.
  - For set 4 under **C** (no validation loop): give the model the hypothesis and the results file and parse its stated verdict; compare.
- **Set 2 scoring:** take paper ids from the reply's **Sources/tool provenance**, not only regex on text; precision = share of cited ids that **resolve** (Crossref/arXiv lookup, cached).
- **Set 3 scoring:** use the real configured embedder; parse the top-3 hypotheses from the structured `hypothesis_generation` output; keep rubric + similarity + human-review flags.
- Before a live run, print the estimated total cost and require confirmation (`--yes` to skip). Keep `--sets`, `--configs`, `--limit`, `--repeats`.
- Optional gated smoke test `ARAITCHI_LIVE_BENCH=1` runs 1 item per set on config A.

## Part 2 — Real fixtures, built from data (no invented gold answers)
Write `scripts/build-bench-fixtures.mjs` (network, run once; commit the output). **Every item must carry a verifiable source** (DOI / OpenAlex id / URL).
- **Set 2 — Literature recall (30):** select 30 real **survey/review papers** in AI and engineering from OpenAlex (published 2018–2025, ≥ 60 references, varied topics; no two on the same topic). Question = "Find the key prior work on <survey's topic, paraphrased from its title/abstract without naming the survey>". Gold = the survey's `referenced_works`, keeping the 30 most-cited, stored as DOIs/arXiv ids. `yearTo` = survey year (so the survey itself is excluded). Store the survey id as the source.
- **Set 1 — Verifiable questions (40):** generated from data, checkable by code — e.g. publication year, venue, first author, DOI of a uniquely titled paper (from OpenAlex metadata), plus closed-form quantitative items whose expected value the harness computes itself. No duplicates; varied topics.
- **Set 3 — Rediscovery (15):** candidate items for well-documented findings (the finding paper's DOI, year, a one-sentence gold statement, required key terms, `yearTo` = year − 1). Mark every item `verified: false`; the report **excludes unverified items from headline numbers** and lists them for the owner to review. Provide `pnpm bench:review` to mark items verified after human review.
- **Set 4 — Validation (10):** each item = a hypothesis + a real or analytically derivable outcome encoded as `results.json` matching the Task 8 contract, with the reasoning/source for the expected verdict; mix of supported, refuted and inconclusive (e.g. missing runs).
- `pnpm bench:validate-fixtures`: checks every DOI/id resolves, no duplicate questions, every item has a source; CI runs the offline part (schema, duplicates, required fields).
